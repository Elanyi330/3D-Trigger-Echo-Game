# M1.75 设计：统一角色武器持握 + 近战/手雷伤害 CS 对齐

> 日期：2026-08-10 · 分支 feat/m1-assets（单目录 /Users/elanyi/Projects/Trigger-Echo）
> 前置状态：M1.5 验收通过，GUT 158/158 全绿（本轮改动前基线已复核）。
> 用户原要求（逐字核心）："玩家、队友、敌人的角色建模完全一致，仅颜色上不同。先构建统一角色模型按要求握持各类武器的动作和样式，然后在角色模型的眼睛处挂载一个摄像头作为玩家端第一人称视角。可以对玩家端第一人称视角做一些微调，但核心动作是不变的。"

## 一、现状诊断（三个根因，全部有代码证据）

### 1.1 刀/手雷"伤害过高"的真根因：双重结算 bug（不是数值写错）

- `weapon_knife.tres` **已经是 CS 数值**：首挥 40 / 连击 25 / 重刺 65 / 背刺 180（秒杀）。
- 但 `Enemy` 有**两个独立碰撞体**且都带 `take_damage`：躯干胶囊（Enemy 本体）+ 头部球（`HeadHitbox`，`take_damage` 转发给本体）。
- `MeleeController._query_physics_targets()`（球扫掠）与 `Grenade._apply_blast_damage()`（形状查询）会**同时命中两者**，去重逻辑（按 collider 身份/ID）拦不住"本体+转发 hitbox"组合 → **每次伤害 ×2**：
  - 轻击连击 25×2 = **50**（用户体感"轻击50"）
  - 重刺 65×2 = **130**（一击必杀，用户体感"重击100"）
  - 手雷 98×2 = **196**（脚下爆炸也秒杀——直接违背 CS 行为）
- CS 规则：头部 ×4 只属于 hitscan 枪弹；**近战与爆炸无部位倍率**（现有代码注释也是这么声明的，只是没防住双 hitbox）。
- 修复：近战/爆炸结算**跳过 group "head" 的目标**（hitscan 路径不受影响，爆头 ×4 保留）。

### 1.2 手雷数值与 CS 不符（半径偏小 + 阶梯衰减非 CS 曲线）

调研来源：CS:GO 泄露源码（hegrenade_projectile / basegrenade_shared 本地下载核实）+ Source 引擎 RadiusDamage + 社区实测数据点 + 现有权威表。

| 项 | CS（CS:GO/CS2 现行） | 本项目现状 | 修复 |
|---|---|---|---|
| 中心最大伤害 | **98**（无甲；+2 撞击≈100 但不可依赖） | 98 ✓ | 不变（100HP 无法被雷直接秒杀 ✓） |
| 衰减公式 | **线性**：`dmg = max(0, D·(1 − d/R))`（Source RadiusDamage：falloff=D/R，实测 1m≈88-89 吻合） | 三段阶梯 [98,60,30] | 改线性公式 |
| 半径 | ~350u ≈ **8.89m**（旧代码注释 D×3.5=343u；Fandom wiki 称 384u=9.75m——.tres 一个字段可切换） | 6m | 8.89m |
| 距离测量 | 爆心→目标**最近体表点**（脚下爆炸≈距离0→98） | 爆心→目标原点（脚部） | Enemy 提供胶囊最近点接口 |
| 墙体 | LOS 遮挡大幅削减 | 完全无视墙体（穿墙满伤） | 加射线遮挡判定：遮挡=不受伤（近似 CS；已知简化：CS 薄墙有渗漏） |

### 1.3 敌人持枪 = 与玩家系统完全割裂的临时 hack

现状：`Enemy._equip_random_weapon()` = 右臂单骨旋转 −50° + `BoneAttachment3D` 挂 `Hand_R` + 四武器共用一组固定欧拉角 (25,180,0)。左手完全不参与，武器在身侧随意挂着。玩家第一人称则是另一套独立构造（ViewModel 程序化方块手臂 + WEAPON_FRAME 逐武器缩放）。**两套系统零共享**——正是用户指出的架构错误。

## 二、方案对比

| 方案 | 内容 | 结论 |
|---|---|---|
| **A：统一 GripRig**（选定） | 新建共享组件：对 Soldier_Echo 骨架做**双臂两骨 IK**，手骨精确到达武器 `_GripRight/_GripLeft` 标记；持枪姿态数据表**唯一来源**；玩家=同一模型的相机挂眼位（隐藏头网格），敌人/未来队友复用同一组件同一数据 | ✅ 完全满足用户原要求；M3 队友零成本复用 |

| C：玩家真模型、敌人维持现状 | 部分统一 | ❌ 仍两套逻辑，一致性要求不满足 |

## 三、详细设计（方案 A）

### 3.1 新组件 `Character/GripRig.gd`（共享持枪 rig）

职责：给定 Soldier_Echo 骨架 + 武器场景，姿态化角色持枪；每物理帧 IK 解算，手永不脱把（ViewModel"构造保证"理念原样继承，从方块手臂升级为真骨骼）。

> **手的保真度约束（用户明确）**：**不做任何精致手模**。手 = Soldier_Echo 现有方块手（0.10×0.11×0.13 盒，Minecraft 方块手臂风格），与 M1.5 视图模型手臂同款。GripRig 只负责把这块方块手**摆到握把标记位**（位置+朝向贴合），不建模手指/握持细节。禁止为此新增任何手部资产或高精度网格。

- `setup(skeleton: Skeleton3D)` / `equip(weapon_scene, resource)` / `unequip()`
- **GRIP_STYLE 表**（唯一持握数据源，取代 `ViewModel.WEAPON_FRAME` 与 `Enemy.ENEMY_WEAPONS` 两处分散参数）：
  - 每武器：WeaponMount 位姿（眼位/躯干相对位置 + 欧拉角）、双手标志（有无 `_GripLeft`）、非持握手空闲姿态
  - 数值由渲染对比调参定稿（步枪双手举枪、手枪单手前举、刀竖持、雷掌心握）
- **武器挂载**：`WeaponMount`（Node3D，角色根子节点）→ 武器实例；mount 位姿 = GRIP_STYLE + 动画层偏移（见 3.3）
- **双臂两骨 IK**：肩关节 → 肘 → 手中心，目标 = 武器标记世界位（余弦定理解肘位 + 极向向量防翻转）；手骨旋转对齐握持朝向（手块与握把贴合）
- 换武器 = unequip + equip（旧武器实例释放、手臂重解）

### 3.2 角色资产小改（build_character.py）

- Soldier_Echo 单蒙皮网格 → **拆两件蒙皮网格**：`Body`（无头）+ `Head`（头+眼）——同一骨架、同比例、同一 build 脚本产出（"同一模型"不变）。玩家隐藏 Head（相机在头内），敌人两件都显示。
- 玩家眼位**保持 1.63m（CS 64u）不动**——全部已验收数值的基准；方块风模型画的眼睛位置略高，属用户允许的"第一人称微调"范畴。

### 3.3 玩家侧重构

- Player 下实例化玩家 Soldier_Echo（玩家绿），隐藏 Head 网格；现有 Head 节点相机不动（眼位 1.63m 恰在模型头盒内）。
- `WeaponView` **保留全部手感动画数学**（kickback/sway/bob/reload 多相位/swing/throw/deploy/ADS 包络），输出目标由 ViewModel 盒子改为 GripRig 的 mount 偏移与相机通道——IK 每帧重解，手自动跟随武器（与现状"手追握把标记"同构）。
- **ADS**：沿用 `_Sight` 标记反推逻辑，目标改为解算 mount 位姿使瞄具落在眼线轴上；举枪姿态由 IK 得出。
- **退役**：`ViewModel.gd`（方块手臂/WEAPON_FRAME/视图缩放 ×2.0/×1.5/×2.2）、`WeaponView._build_body` 假盒子下半身 → 由真模型身体替代（站立姿态；**真实尺寸武器**——玩家与敌人持枪视觉完全一致）。
- 相机 pitch → 手臂链俯仰（武器指向视线）；yaw = 身体朝向（现有行为）。
- 下蹲：下半身保持站姿渲染（与现状假盒子同等近似，**不回归**）；完整蹲姿动画归 M3。

### 3.4 敌人侧重构

- `Enemy._equip_random_weapon()` → `GripRig.equip(随机武器)`；删除 `ARM_RAISE_DEG` 与固定欧拉角表。
- 敌人持枪 = 与玩家**同一组件、同一数据表**的产物（AK 双手据枪、Glock 单手持、刀竖持、雷掌心握）。

### 3.5 枪口火光/曳光/弹孔

- 火光仍 re-parent 到武器 `_Muzzle` 标记（跟随 rig 上的武器实例）；hitscan/曳光起点仍为相机（不变）；弹孔 quad 方案不变。

## 四、手雷数值修复（对标 §1.2 表）

1. `Grenade.damage_in_radius(d)` → `max(0, damage × (1 − d/blast_radius))`（线性）。
2. `weapon_m67.tres`：`blast_radius` 6 → **8.89**；删除 `blast_falloff` 阶梯表字段（`Weapon_Resource.gd` 同步删字段；公式参数 = damage + blast_radius，数值唯一来源仍是 .tres）。
3. 距离测到目标最近体表点：`Enemy.explosion_nearest_point(blast_pos) -> Vector3`（胶囊最近点）；Grenade 结算时 `target.has_method` 探测调用，无则退化为 `global_position`。
4. LOS：爆心→目标点射线（Objects+地形层）被遮挡 → 该目标不受伤。
5. 更新 `cs2-weapon-data.md`（半径/公式/遮挡行为 + 本轮来源注记）。

## 五、近战数值修复

1. `.tres` 不动（已 CS）。
2. `MeleeController._resolve_swing` 与 `Grenade._apply_blast_damage`：跳过 `is_in_group("head"` 的目标。
3. 回归测试锁定（真实 Enemy 构造，含 HeadHitbox）：
   - 轻击一次 = 恰好 40（非 80）；手雷脚下爆炸 = 恰好 98 一次（非 196、不死）。

## 六、测试策略（TDD，RED 先行）

新增失败测试（实现前写）：
1. 近战对真实 Enemy（躯干+头 hitbox）单击仅结算一次首挥 40
2. 手雷对真实 Enemy 仅结算一次；脚下爆炸 98 且目标存活（100→2 HP）
3. `damage_in_radius` 线性：0m=98 / 4.445m≈49 / ≥8.89m=0（对比旧阶梯断言全部重写）
4. LOS 遮挡目标不受伤
5. GripRig：equip 后武器 `_GripRight` 与右手骨位置重合（容差内）；有 `_GripLeft` 武器左手解算到标记；换武器旧实例释放
6. 玩家装配：Player 下有 Soldier_Echo 实例且 Head 网格隐藏；WeaponView 不再创建 ViewModel 盒子
7. 敌人装配：Enemy 随机武器经 GripRig（双手武器左手到位）
8. 现有 158 测试保持绿（其中手雷 1m/3m/5m 阶梯断言按新公式重写——这是**有意行为变更**）

- CS 对比 agent 终审（按 M1.5 验收 pipeline）

## 八、验收标准（交付后用户亲自游玩）

1. 敌人持枪姿态正确（双手据枪/单手持/竖持刀/掌心雷），与玩家持枪为同一套动作样式
2. 第一人称看到自己的手臂（真模型）持枪；切枪/开镜/换弹/挥刀/投雷动作完整
3. 刀：轻击 40（连击 25）、重刺 65 两下不死、背刺秒杀
4. 手雷：脚下爆炸最高 98（剩 2 HP 不死）；远距离伤害平滑衰减至 ~9m 边缘为 0；隔墙不受伤
5. GUT 全绿 + 无性能明显劣化

## 九、不做（YAGNI / 后续里程碑）

- **精致手模/手指握持细节**（用户明确：方块手即可，永不新增手部资产）
- 腿部走/跑/蹲动画（M3）；换弹左手插匣/拉环动画（M2+）；队友实体（M3，GripRig 即插即用）
- 薄墙渗漏、stab 射程分级、连击窗口严格化、整匣丢弃（M1.75 候选清单遗留项，不在本轮用户请求内）
- 新武器型号（M5）
