# M2 小地图（圆形 2D 雷达）设计方案

> 日期：2026-08-13 · 分支 feat/m1-assets · 状态：**已拍板（2026-08-13）**——渲染方式 **A 数据驱动蓝图投影**；地图半径 **12m**（用户：不可过大，12m 内敌人全显）；实施中
> 需求（用户原话）：屏幕左上角添加圆形 2D 地图；地图朝向 = 玩家面对方向；显示周围一定范围的组件投影 + 敌方/友方标志。其他优化放下一步。

---

## 一、渲染方案（拍板点 1）

### 方案 A：数据驱动 AABB 蓝图投影（推荐）

**原理**：小地图不再渲染 3D 场景，而是直接消费 `map_layout_v3.gd` 的 `all_solids()` 数据表（193 个 `{name, kind, center, size}` 实体），把每个实体的顶视 AABB 投影到以玩家为中心的旋转 2D 坐标系，`_draw()` 画轮廓线。

**投影流水线（纯逻辑，可单测）**：
```
世界坐标 → 平移（−玩家位置）→ 绕 Y 旋转（−玩家 yaw，使玩家朝向恒指地图上方）
→ 缩放（像素/米）→ 圆形裁剪（半径外剔除 + 线段-圆几何裁剪）
```

**实施细化（拍板后定稿）**：圆形裁剪不用 shader——在 MinimapCore 内做**线段-圆求交几何裁剪**（每段实体边线解二次方程求可见子段），渲染层只画多边形折线 + `draw_circle` 底色 + `draw_arc` 描边。全部数学落在纯逻辑核心，可单测。

**优点**：
1. **风格天然匹配**——方块灰盒地图的顶视线框 = 蓝图效果，美术升级后数据不变照常工作
2. **确定性可单测**——纯数学变换，MinimapCore 全部行为 GUT 直测（旋转/裁剪/投影），符合项目 TDD 铁律
3. **零额外渲染开销**——193 矩形 × 4 点变换，每帧成本可忽略；无需第二相机、无需图层管理
4. 数据同源（`LAYOUT.all_solids()` 与跳跃记录器/探针同一数据表）——地图改布局小地图自动跟随，布局哈希变更亦自动一致

**缺点**：无高度信息（俯视平面图，非 2.5D 阴影图）；不显示装饰（decor 无碰撞实体本就不在 all_solids 中，符合"组件投影"语义）。

### 方案 B：SubViewport 顶视正交相机（备选）

真实 3D 顶视渲染到 SubViewport，圆形遮罩显示。优点：视觉真实、含高度阴影。缺点：需第二相机 + 图层管理（避免把玩家视模型/天空/粒子渲染进地图）+ 敌人模型顶视太小难以辨认（仍需叠标志）+ 渲染一帧全图开销 + 难单测。**不推荐现阶段**（灰盒期 A 的蓝图观感更优；若未来视觉升级后想换 B，数据层不变可迁移）。

## 二、视觉规格

| 项 | 规格 |
|---|---|
| 位置 | 屏幕左上角，边距 16px |
| 直径 | 默认 180px（export 可调；**用户 2026-08-13 复测拍板放大 1.5× → 半径 135px/直径 270px**） |
| 圆形裁剪 | 小 shader（半径外 discard）+ 2px 环形描边 + 半透明暗底（alpha≈0.5，不挡视线） |
| 组件投影 | 顶视 AABB 轮廓线（1px，浅灰绿，与方块风一致）；按 kind 过滤（ground 底板跳过不画，墙/cover/柱/建筑全画） |
| 玩家 | 中心固定绿色箭头（恒指上方——地图旋转式，CS 雷达同款） |
| 友方 | 绿色圆点（M3 队友出现前只有玩家中心箭头，接口预留） |
| 敌方 | 红色圆点（与游戏内敌红/玩家绿配色一致） |
| 地图范围 | **半径 12m**（用户拍板：不可过大；export 可调）——24m 直径局部雷达 |

## 三、敌人显示策略（拍板点 2）

- **方案 1：半径内全显（✅拍板默认）**——**12m** 内所有敌人红点，简单直接。当前敌人是 StaticBody 桩（不移动不藏匿），全显合理；等 M3 移动 AI + 战术隐藏出现后，可切换方案 2。
- **方案 2：CS 式可见才显**——仅显示玩家视线可见（LOS 射线）的敌人，视野盲区不显示。更硬核、对标 CS 雷达，但现阶段桩敌人全静止、全显/半显差异小。

两种做成配置开关（`show_enemies: ALWAYS / LOS_ONLY`），拍板默认值即可。

## 四、架构（可测性优先，沿用项目模式）

```
MinimapCore（纯逻辑，class_name，可单测）
  输入：玩家位置/yaw、all_solids()、实体列表[{pos, is_enemy}]、config(radius_m/像素半径)
  输出：投影矩形数组 + 标志点数组（地图局部坐标，y 轴=玩家朝向）
        + 圆形裁剪结果（半径外剔除）

Minimap（Node2D 场景胶水，_draw 消费 core 输出）
  挂 L_M2 的 HUD CanvasLayer 左上角；每物理帧取玩家 transform + L_M2 提供的敌人列表

L_M2 装配：
  Minimap.new() → HUD 层
  setup(LAYOUT.all_solids(), 玩家, 敌人枚举闭包)
  敌人枚举：遍历 L_M2 子节点 `is Enemy`（≤5 个，每帧枚举零成本；M3 起队友同样注入）
```

**数据流约束**：小地图只读数据，不持有游戏状态；敌人 died 自动从枚举消失（节点 free）。

## 五、TDD 断言清单

1. 投影数学：世界点 (0,0,−10)（玩家正前方）→ 地图坐标 (0, +pixel)；右侧 +X → (+pixel, 0)；yaw=π/2（面朝 −X）时同一世界点 (−Z) 投影到地图 +X 方向（玩家右侧）
2. 实体矩形：center/size → 4 角投影后矩形保形（边长=size×scale）
3. 范围剔除：中心距 >12m+半对角 的实体不产出；恰在内产出；标志点 >12m 剔除
4. 线段-圆裁剪：矩形全在圆内 → 4 段完整；矩形跨圆 → 每段端点恰在圆上（距心 ≈半径，容差）；全在外 → 0 段
5. ground kind 跳过；玩家恒在 (0,0)
6. 敌/友标志 is_enemy 一致；确定性（同输入同输出）
7. 集成冒烟：L_M2 场景 Minimap 每帧产出 ≥1 段（地图非空）
