## 规格

### 常量与状态（auto_traversal.gd）

常量区（紧跟 `ANCHOR_REACH_EPS` 后）：

```gdscript
const WP_TIMEOUT := 8.0      # 途经点进展超时（F13）：8s 未推进 → 强制重寻路
const SEG_MOVE_MIN := 0.2    # 到达推进需本段实际位移 ≥ 此值（F13 防冻结点假到达重置卡死）
const MAX_REPLANS := 2       # attempt 级重寻路次数上限（F13：原一次性 → 2 次有界）
```

状态区变更：

```gdscript
var _replan_count := 0               # 重寻路计数（F13 替代 _walk_replanned: bool）
var _wp_t := 0.0                     # 当前途经点累计计时（F13）
var _seg_move_origin := Vector3.ZERO # 当前段起点（F13 到达推进位移校验基准）
```

### 1. `_walk_replanned: bool` 全站替换为 `_replan_count: int`

- 删除 `var _walk_replanned := false` 声明，替换为上面三行
- `_begin_attempt`：`_walk_replanned = false` → `_replan_count = 0` + `_wp_t = 0.0` +
  `_seg_move_origin = _player.global_position`（`_anchor_fallback_done = false` 行保留）
- 新增 helper（`_replan_from_current` 定义之后）：

```gdscript
## 有界重寻路（F13）：计数 < MAX_REPLANS 才执行；成功置 _seg_idx=0 返回 true。
## 全部重寻路调用点统一走此入口（行走坠落/卡死/途经点超时/锚点回退）——防无限重寻路挂死。
func _try_replan_from_current() -> bool:
	if _replan_count >= MAX_REPLANS:
		return false
	_replan_count += 1
	return _replan_from_current()
```

- 调用点替换（**四处**）：
  1. `_walk_tick` 行走坠落分支：`if _feet_y() < … and not _walk_replanned:` → `if _feet_y() < …
     and _replan_count < MAX_REPLANS:`；内层 `if _replan_from_current():` → `if _try_replan_from_current():`
  2. `_walk_tick` 卡死分支：`if not _walk_replanned and _replan_from_current():` →
     `if _try_replan_from_current():`
  3. T3 锚点回退分支（`_enter_jump` 内）：`if not _anchor_fallback_done and _replan_from_current():`
     → `if not _anchor_fallback_done and _try_replan_from_current():`
     （`_anchor_fallback_done` 守卫保留；调用走统一入口计数）
  4. **滑墙可达性守卫**（T1 修复循环新增，`_walk_tick` 滑墙块前）：
     `if not _walk_replanned and _replan_from_current():` → `if _try_replan_from_current():`
     （守卫其余逻辑不动；重寻路不可用分支 `_wall_follow = false; return` 保留——
     F13 途经点超时接管其有界性）

### 2. 途经点进展超时（_walk_tick）

- 函数开头（`_seg_idx >= _segments.size()` 检查之后、seg 解析之前）：`_wp_t += delta`
- `_arrived` 推进分支（`_seg_idx += 1` 处）：`_wp_t = 0.0` + `_seg_move_origin = _player.global_position`
- 检查顺序（在 `_arrived` 判定**之前**）：

```gdscript
	# F13 途经点进展超时：8s 未推进（轨道转圈/高度门挡住/压墙振荡）→ 强制重寻路；
	# 计数耗尽仍无进展 → 有界 stuck 裁决（EastTower 类 30-70s 白转/冻结的压缩）
	if _wp_t > WP_TIMEOUT:
		if _try_replan_from_current():
			_wp_t = 0.0
			_seg_move_origin = _player.global_position
			_reset_stuck()
			return
		_teleport_to(_spawn)
		_teleported = true
		_end_attempt("stuck", "途经点 %ds 无进展" % int(WP_TIMEOUT))
```

（`_teleport_to`/`_teleported`/`_end_attempt` 与既有 stuck 路径同口径）

### 3. 到达需位移（_walk_tick）

`_arrived(waypoint)` 判定分支加位移校验：

```gdscript
	if _arrived(waypoint) and Vector2(
			_player.global_position.x - _seg_move_origin.x,
			_player.global_position.z - _seg_move_origin.z).length() >= SEG_MOVE_MIN:
		_seg_idx += 1
		_wp_t = 0.0
		_seg_move_origin = _player.global_position
		_reset_stuck()
		return
```

（位移不足 → 不推进，继续走，交途经点超时/卡死兜底——冻结点附近途经点不再假到达
重置卡死计时）
