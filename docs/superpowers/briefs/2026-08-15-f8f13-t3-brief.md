状态区（`_walk_replanned` 声明附近）：

```gdscript
var _anchor_fallback_done := false  # 锚点不可达重寻路一次性守卫（F10，跨 attempt 状态泄漏防护）
```

### _enter_jump 末尾预检（F10）

在 `_speed_gate_relaxed` 计算块之后、`_air_t = 0.0` 之前插入：

```gdscript
	# F10 锚点可达性预检：锚点面高 − 脚高 > STEP_MAX(0.62) + 容差 → 步行不可达
	# （箱顶锚点 + 人在箱底类压墙 23s 的根治——0.8m > step-up 0.62 走不上去）。
	# 重寻路一次（新路径可含 Crate_WS 类上箱链接 → 正常执行）；仍不可达 → 诚实失败。
	# 不判「锚点低于脚」：下行走下边缘是设计内，TO_ANCHOR 坠落重试已兜底。
	if _waypoint_surface_y(_anchor) - _feet_y() > 0.62 + ANCHOR_REACH_EPS:
		if not _anchor_fallback_done and _replan_from_current():
			_anchor_fallback_done = true
			return
		_end_attempt("jump_missed", "锚点不可达（面高差 %.2fm）"
				% (_waypoint_surface_y(_anchor) - _feet_y()))
		return
```

### _begin_attempt 重置

`_begin_attempt` 中 `_walk_replanned = false` 一行后追加：

```gdscript
	_anchor_fallback_done = false
```

### 机制说明（brief 写明，不需代码）

- `_replan_from_current()` 重排 `_segments` 并置 `_seg_idx = 0`，状态机落回 WALK——新路径
  首跳锚点可达则正常执行；`_anchor_fallback_done` 保证重寻路只试一次（第二次再遇不可达
  锚点 → 立即诚实失败，防重寻路→同链接→重寻路死循环）
- 垂直链接（F12）豁免无需代码：其锚点 = 箱底导航点（面高差 0），预检天然通过
- `_end_attempt` 与 `_replan_from_current` 均为既有函数，不改实现
- 步高阈值 0.62 引用 `MovementController.STEP_MAX`？**不**——auto_traversal.gd 无 STEP_MAX
  常量，直接写字面量 0.62 并注释出处（MovementController.STEP_MAX，控制器级注释已列
  偏离理由）；跨文件 preload 不值得（T2 简报已批准字面量口径）
