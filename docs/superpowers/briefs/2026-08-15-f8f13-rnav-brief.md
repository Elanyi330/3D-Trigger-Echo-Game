> 审查对象：T-nav 实现子代理对 `tools/bake_navmesh.gd`、`tools/probe_navmesh.gd` 的改动
> 与重烘焙产物 `Levels/M2_TDM/navmesh.res`（工作区 diff，含 auto-commit 已入库的部分）。
> 规格来源：`docs/superpowers/briefs/2026-08-15-f8f13-tnav-brief.md`。
> 背景：`docs/superpowers/specs/2026-08-15-auto-traversal-runup-fixes-design.md` 用户拍板方案 A。

## 审查流程

1. `git diff` 看 bake/probe 两文件全部改动 + `git status` 确认无越界改动（尤其确认
   auto_traversal.gd / test_auto_traversal_runup.gd / map_layout_v3.gd 未被触碰）
2. 读简报逐条核对规格合规（含实现者报告的偏差项——④ 门禁采样公式按 RED 锚修订，
   逐条判断修订是否合理）
3. 独立跑验证（全量，允许 5-8 分钟）：
   - `godot --headless --path . -s tools/probe_navmesh.gd`（①-④ 全过 exit 0）
   - `godot --headless --path . -s tools/probe_v3_walk.gd`（79/79）
   - `godot --headless --path . -s tools/probe_jump_edges.gd`（exit 0）
   - 全量 GUT（预期 394/394 **或** 393/394+1 failing（WestTowerBox stuck）——取决于
     T1 修复循环是否已收官；两者皆可，只需如实报告数字，不据此判定 T-nav）
4. 布局哈希核实：`git diff` 中 map_layout_v3.gd 无变化（哈希不变 → 记录不重置铁律）

## 两个裁定（都必答）

- **规格合规 ✅/❌**：斜坡替身参数与 map_layout_v3.gd L164-165 逐字一致；跳过条件仅
  West/EastTowerRamp 前缀（RampE/RampW 未动）；绕序两侧向上（叉积证据）；运行时自检
  断言存在且通过；④ 门禁采样/容差修订合理（实现者声称旧 navmesh 上字面规格全过——核实其
  RED 证据的 5/22 列失败是否真锚住旧缺陷）
- **代码质量 ✅/❌**：注释口径（中文、注明 2026-08-15 方案 A）、无死代码、烘焙参数其余
  全部未动、无临时诊断文件残留

## 重点风险清单（逐项核实）

1. 替身斜坡与物理台阶的语义等价性：门禁容差 0.35 覆盖「导航面 vs 物理台阶顶 ≤0.125」+
   导航偏移 0.4 口径 + 侵蚀余量——核实 ④ 的期望值公式与容差推导
2. ④ 门禁的「高查」列（自上而下查询）是否真能抓悬空面族（防只抓低位面掩蔽）
3. 烘焙产物多边形数 1097 与历史基线 1087 的差异归因（实现者称东塔绕序修正 +13——
   合理；另核对 probe_jump_edges 的哈希/覆盖门禁通过是否依赖 navmesh——若依赖则需
   确认重烘焙未破坏其口径）
4. 实现者报告的「坡脚残余悬空桥面 ≤0.35」——门禁容差内但在 walker 到达门（0.3）边界：
   记 Major 或 Minor 发现（供 T1 修复循环/T4 参考），不阻塞本审查
5. auto-commit 中间态（93d2f03 等）是否在最终工作区留下残留——以当前工作区状态为准

## 返回格式

```
裁定：规格合规 ✅/❌ + 代码质量 ✅/❌
发现：[Critical|Major|Minor] 每项：位置（文件:行）+ 问题 + 证据
验证：probe_navmesh/probe_v3_walk/probe_jump_edges/GUT 实际数字
结论：APPROVE / APPROVE_WITH_NOTES / REJECT
```

Critical = 与简报规格冲突或门禁破坏；Major = 导航语义风险；Minor = 注释/风格/残余。
无 Critical/Major 且门禁绿 → APPROVE（可附 Minor 清单，不阻塞）。
