# 任务简报 T-nav：塔坡道 navmesh 烘焙替身修复（用户拍板方案 A）

> 项目：Trigger Echo（Godot 4.7.1，GDScript）。分支 feat/m1-assets，单目录 `/Users/elanyi/Projects/Trigger-Echo`。
> 背景：2026-08-15 用户拍板方案 A——塔坡道台阶区 navmesh 数据缺陷用「烘焙替身」根治：
> **游戏几何/视觉/碰撞/布局哈希全部不动**，只在烘焙几何里用真斜坡替代台阶盒。

## 缺陷证据（已由控制器探针实锤，勿重新调查）

- 西塔坡道 navmesh 多边形 637：三角形顶点 (-22.10,0.40,7.90)/(-18.60,1.40,6.65)/(-20.10,0.40,10.15)
  ——斜跨 5m 的倾斜多边形直连地面→塔基顶；物理上该区域是 10 级台阶（0.62 深 × 0.25 高，
  顶面 0.25…2.5）+ 塔基（z∈[-2,2] 到不了 8.4）
- 物理射线实测：z=8.4 处表面=Ground 0.0（navmesh 面高=0.5）；z=6.65 处=Step3 顶 0.75
- 东西两塔镜像同款（西 16 多边形/东 13 多边形全部无台阶顶面多边形，全是 y∈[0.4,1.4]/
  [1.4,2.8] 倾斜多边形）
- 根因：bake_navmesh.gd 的「水平边 <1.2 放大到 1.2」规则把台阶 z 深 0.62 放大成 1.2，
  相邻台阶烘焙盒重叠 0.58m，高度冲突把台阶顶面埋掉
- 后果：遍历走廊路径途经点面高与物理差 0.5m > 到达高度门 0.3 → 永不到达转圈；
  用户实机 EastTower 21s 楔死同族

## 规格

### 1. bake_navmesh.gd 修改

1. 塔坡道台阶实体**跳过**烘焙（`if nm.begins_with("WestTowerRamp") or nm.begins_with("EastTowerRamp"): continue`
   ——放在 decor 跳过之后、Rail 判定之前；注意**只跳这两组**，祭坛坡道 RampE/RampW 不动（它们工作正常））
2. 台阶区烘焙几何用真斜坡四边形替身（两塔，参数与 map_layout_v3.gd L164-165 逐字同步）：
   ```gdscript
   # 塔坡道烘焙替身（2026-08-15 用户拍板方案 A）：台阶整高盒烘焙几何互相重叠（窄边
   # 放大 1.2 后相邻盒叠 0.58m）把台阶顶面埋掉 → 烘焙出斜跨 5m 的悬空多边形（poly 637
   # 实锤）。替身=真斜坡平面（物理台阶经 step-up 0.25≤0.62 可走，导航面表达为斜坡是
   # 物理语义的忠实近似；斜坡梯度与台阶顶差 ≤0.125m < 到达高度门口径 0.3）。
   # 参数与 map_layout_v3.gd _ramp_steps 调用逐字同步（勿改布局，仅此处烘焙替身）。
   const TOWER_RAMP_SLOPES := [
       {"x0": -21.0, "x1": -18.5, "z0": 8.2, "z1": 2.0, "y0": 0.0, "y1": 2.5},
       {"x0": 18.5, "x1": 21.0, "z0": -8.2, "z1": -2.0, "y0": 0.0, "y1": 2.5},
   ]
   ```
3. 斜坡四边形构造（SurfaceTool 两三角；**绕序必须两侧都向上**——控制器实验已证西塔
   绕序 [0,2,1][0,3,2] 可烘出、东塔未烘出上段——你需实测迭代到两侧都烘出为止；
   法线 set_normal(Vector3.UP)，顶点：v0=(x0,y0,z0) v1=(x1,y0,z0) v2=(x1,y1,z1) v3=(x0,y1,z1)）
4. 烘焙前运行时自检断言：LAYOUT.all_solids() 中 WestTowerRamp/EastTowerRamp 前缀实体
   恰好各 10 个、且其包围盒与 TOWER_RAMP_SLOPES 参数吻合（x/z 范围 ±0.01）——布局参数
   变更时烘焙脚本立即报错而非静默漂移（同步注释铁律的运行时兜底）
5. 其余烘焙逻辑（agent_radius 0.25 / climb 0.62 / cell 0.25 / 窄边放大 1.2 / Rail 豁免）
   **一律不动**

### 2. 重烘焙

`godot --headless --path . -s tools/bake_navmesh.gd` → 覆盖 `Levels/M2_TDM/navmesh.res`。
多边形数应为 ~1084（原 1087；实验参考值 1084）。

### 3. probe_navmesh.gd 新增门禁 ④（TDD：先写、旧 navmesh 上必失败=RED，重烘焙后 GREEN）

```gdscript
# ④ 塔坡道台阶区导航梯度（2026-08-15 方案 A 门禁）：沿两塔坡道中心线（x=∓19.75）
#   在 10 个台阶槽中点 z=z0±0.31*(i+0.5)（i 0..9，台阶槽深 0.62 的一半）采样
#   map_get_closest_point：导航面高 −（0.4+该处物理台阶顶）≤ 0.35 判过。
#   物理台阶顶 = 0.25*(i+1)（台阶 i 顶高，i 从 0 起）。旧缺陷 navmesh 在 z=8.4 处
#   导航面高 0.9 vs 物理 0 → 差 0.5 必失败（RED 锚）；斜坡替身后梯度差 ≤0.125。
```

采样点与期望（西塔 x=-19.75，东塔 x=19.75，z 每槽中点）：
`z_i = z0 + (z1-z0)*(i+0.5)/10`，物理台阶顶 `0.25*(i+1)`，期望导航 y ≈ `0.4 + 0.25*(i+1)`。
容差 0.35（导航偏移 0.4 口径 + 台阶级差 0.125 + 侵蚀余量）。
