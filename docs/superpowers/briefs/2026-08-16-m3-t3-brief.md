## 接口块（精确签名，照抄）

```gdscript
# bot_locomotion.gd 常量区追加
const RUNUP_TURN_GATE := 0.3      # rad：助跑转向门（遍历器 F8 验证值）
const RUNUP_GATE_SPEED := 4.0     # m/s：触发速度门（遍历器验证值）
const TRIGGER_CONE := 0.9         # 方向锥 cos 系数（±25°，遍历器 F9 验证值）
const JUMP_TIMEOUT := 2.5         # s：起跳→落地判定超时
const JUMP_ARRIVE := 0.8          # m：助跑到达起跳点判定半径（水平距）
const LAND_TOLERANCE := 1.5       # m：落地判定容差（距段终点水平距）
const LINK_SNAP := 0.5            # m：路径点对与链接端点匹配容差（双向距离）

# static 纯函数（T3 新增）
static func classify_segments(points: PackedVector3Array, links: Array) -> Array
# links = setup 时一次预对齐端点表 [{name, from:Vector3, to:Vector3}]（见语义 1）
# 返回 [{type:"WALK", from:Vector3, to:Vector3}, {type:"JUMP", from:Vector3,
#         to:Vector3, link_name:String}]——相邻路径点对与 links 端点双向距离 < LINK_SNAP
# 即 JUMP 段（链接双向注册，from→to 与 to→from 均须匹配）

static func pick_jump_speed(delta_h: float, dist: float, human_p50: float,
        augmented: bool, v_req: float) -> float
# 消费口径（设计 §4.6 拍板哲学）：
#   真实人类 p50（augmented=false 且 human 非空）→ 原值
#   增强样本 p50（augmented=true）→ p50 × 0.9（置信折扣）
#   无人类数据（human_p50 传入 NAN）→ v_req × 1.15
# 最终钳制：clamp(v, r.v_req, r.v_hi)——r = JumpSolver.required_speed(delta_h, dist)
# （v_hi 可为 INF，clamp 对 INF 上界安全）；r.ok=false → 返回 v_req×1.15 且调用方
# 不触发跳跃（诚实失败）。注意 feasibility 返回键为 {ok, verdict, v_req, margin}
# （无 v_min/v_max）。

# 实例状态（T3 追加）
var _penalized_links: Dictionary = {}   # link_name -> 剩余惩罚帧数（重寻路临时加权语义预留）
var _jump_state: Dictionary = {}        # {} | {phase:"RUNUP"|"TRIGGER"|"AIR", seg, t}
```

## 语义规格

1. **setup 扩展**：预对齐链接端点表——`LAYOUT.jump_links()` 每条 {name, from, to} 经
   `NavigationServer3D.map_get_closest_point(map_rid, p)` 对齐（link 注册即导航点，
   L_M2 F4 教训）→ 存 `_links`（Array）。数据集加载：首次使用时 `FileAccess.get_file_as_string
   ("res://Levels/M2_TDM/jump_edges_dataset.json")` → JSON.parse → 静态缓存
   `_dataset_edges: Dictionary`（key = link 名 → edge 条目；遍历 edges 数组按 link_names
   逐名建索引）。
2. **set_target 扩展**：寻路 + 简化后调 `classify_segments(简化路径, _links)` →
   存 `_segments`（与 `_path` 同存；WALK 段保留途经点序列，JUMP 段记 from/to/link_name）。
   T2 的高度门分支由段分类替代：下一途经点属 JUMP 段起点时进入跳跃执行（而非 T2 的重寻路）。
3. **tick 扩展**（T2 途经点弹跳逻辑保留）：
   - 当前段为 WALK：T2 原逻辑（到达弹点/前瞻转向/高度门重寻路）
   - 当前段为 JUMP 时进入 `_jump_state` 状态机：
     - **RUNUP**：朝段起点直线助跑——`absf(angle_difference(rotation.y, target_yaw(body, seg.from))) <= RUNUP_TURN_GATE` 才前进（原地转消除最小转弯圆，遍历器 F8）；水平距 < JUMP_ARRIVE → 进入 TRIGGER
     - **TRIGGER**：`hspeed = 水平速度`；`hspeed >= RUNUP_GATE_SPEED` 且
       `速度方向·段方向 >= TRIGGER_CONE * hspeed` → `command.jump_pressed = true`
       （单帧边沿，控制器自动清零）→ 进入 AIR；TRIGGER 超过 1.0s 未触发（如转向不到位）→
       退回 RUNUP 重对准
     - **AIR**：move_axis 保持沿段方向（空中微调，物理层已有 RUN 档空中控制）；落地判定：
       `body.is_on_floor()` 或 t > JUMP_TIMEOUT → 成败判定
   - **成败判定**：落地位置与段 to 点水平距 < LAND_TOLERANCE 或（数据集边存在时）落地 x/z
     在 landing_zone（center±size/2，膨胀 0.5）内 → 成功（弹段，继续后续段）；否则失败
   - **失败处理**：`jump_failed.emit(link_name)` + `_penalized_links[link_name]` 惩罚 →
     `set_target(原目标)` 重寻路一次；若重寻路后路径仍含该链接（classify 仍出同 link 的
     JUMP 段）→ `clear_target()`（诚实放弃；M3.3 决策层换目标）
4. **pick_jump_speed 数据接入**（调用点）：JUMP 段起点到达时查 `_dataset_edges[link_name]`
   → 边 `delta_h`/`dist_zone`/`human.takeoff_speed.p50`/`human.augmented`/`physics.v_req`
   → `pick_jump_speed(...)` 得 v；**v 用于何用**：触发门控后的初速不直接设定（物理层
   jump 固定 V_JUMP），v 作为**触发速度门动态值**——`RUNUP_GATE_SPEED` 改为取
   `max(v, RUNUP_GATE_SPEED)`（人类 p50 高于基门时按 p50 起跳——参数化执行本体）。
   无数据集边 → 纯默认门（RUNUP_GATE_SPEED）。
5. **T2 兼容**：jump_failed 信号自本任务起真实发出；T2 测试（高度门重寻路行为）不受
   影响（WALK 高度门逻辑保留为无链接路径的兜底）。
